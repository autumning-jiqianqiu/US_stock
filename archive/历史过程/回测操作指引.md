# 回测操作指引(点时基本面 + 动量模式 + 股息记账)

**日期**:2026-10-09
**对应 EA**:`mql5/Experts/US/CrossSectionalRankEA.mq5`

## 一、前视偏差已消除

基本面管线现在支持**点时快照**(`--asof`):按 SEC 每条 XBRL 事实的**实际报送日 `filed`**
过滤,只保留"在那一天已经能看到"的数据 —— 这是严格无前视的做法,不需要假设报送滞后。

已生成两份快照,都放在 MT5 的 `Common/Files`:

| 文件 | 数据截止 | 保留标的 | 用途 |
| --- | --- | --: | --- |
| `fundamentals_2024-12-31.csv` | **2024-09-30**(少数 11 月) | **49 只** | **2025 回测用(无前视)** |
| `fundamentals.csv` | 2026-06-30 | 56 只 | 当前选股用 |

核对:2025 回测用 2024-12-31 的快照,数据全部来自 2024Q3 及更早的财报,
回测期间不可能"看到未来"。

## 二、EA 的四个新输入

| 输入 | 默认 | 作用 |
| --- | --- | --- |
| `InpUseFundFilter` | true | 按快照过滤标的 |
| **`InpFundFile`** | `fundamentals.csv` | **选哪份快照** —— 2025 回测填 `fundamentals_2024-12-31.csv` |
| **`InpPoolFromFile`** | true | **股票池直接取自快照**(fund_keep=1 的标的);关掉才用 `InpSymbols` |
| `InpUseDividend` | true | 累计股息现金并单独报告 |
| `InpRankMode` | 0 | 0=稳定性评分 / 1=区间收益(动量) |

> **为什么股票池要从文件取**:MT5 对字符串型输入参数有长度上限,把 81 个代码塞进
> `InpSymbols` 会被**截断**(实测只传进去 61 个,最后一个是残缺的 `RI`),
> 后面 20 只(RIVN…MRK)根本没参与回测。现在池子直接读快照文件,不再受长度限制。

> MT5 策略测试器**不会**给 CFD 补股息调整(已验证:CFD 报价跟随未复权股价)。
> EA 只能内部记账,结果写在 `Common/Files/cs_run_report.csv`,
> **测试器净盈利 + DividendCash 才是与真实账户可比的口径**。


3. 确认 `Common/Files` 里有 `fundamentals_2024-12-31.csv`(已自动放好)。

## 六、结果怎么看

| 文件 | 内容 |
| --- | --- |
| 测试器「报告」页 | 净盈利 / 最大回撤 / 夏普 / 交易数(**纯价格口径**) |
| `Common/Files/cs_run_report.csv` | `DividendCash`、调仓次数、当前模式 |
| `Common/Files/cs_diag.csv` | 每次调仓每只标的的诊断(为什么买这几只) |

## 七、仍要注意

1. **2025 是样本内**(选股脚本的调参区间)。真正的验证应看 **2026 下半年** ——
   那需要再生成一份 `--asof 2026-06-30` 的快照,区间取 2026-07-01 ~ 2026-10-08。
2. **51 只标的样本仍偏小**,加上 21 天调仓,一年的调仓次数只有十几次,统计意义有限。
3. 首轮慢、之后有缓存会快很多。
