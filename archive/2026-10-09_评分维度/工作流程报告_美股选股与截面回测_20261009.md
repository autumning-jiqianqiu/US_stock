# 美股选股与截面回测 —— 工作流程报告

_2026-10-05 ~ 2026-10-09 ｜ 从「价格稳定性选股脚本」到「含基本面过滤、可回测、已归因的截面策略」_


## 一、目标与范围

起点:一个只能在 MT5 里手动跑的「美股价格稳定性排序」脚本,输出一份排名 CSV,没有收益、没有回测。

终点:一条闭环链路——数据管线(基本面) + 选股脚本(价格统计) + 截面回测 EA + 可复现的参数集 + 归因报告。

| 项目 | 内容 |
|---|---|
| 在范围内 | 品种池清洗与合约解析、价格稳定性指标体系、基本面因子设计与落地、截面调仓回测 EA、四组对照回测与归因 |
| 不在范围内 | 实盘执行、参数寻优(只做了必要的对照)、滑点/冲击成本建模、多经纪商适配 |


## 二、总体流程(六个阶段)

| 阶段 | 目标 | 主要产物 |
|---|---|---|
| S1 环境与数据可达性 | 确认可用的数据源与交易环境 | 数据源可达性清单 |
| S2 标的池清洗 | 把 100 个原始代码映射成可交易合约 | 81 个基础代码池 + 剔除清单 |
| S3 价格稳定性选股 | 把原脚本跑通并产出排名 | reliability_ranking.csv / .xlsx + 排序报告 |
| S4 基本面因子 | 设计并落地因子表,做点时快照 | fundamentals*.csv + 审计文件 + 因子设计文档 |
| S5 截面回测 | 把「排名」变成「可回测的组合」 | CrossSectionalRankEA.mq5 + 4 组参数集 |
| S6 回测与归因 | 跑四组对照 + 基准,定位收益来源 | 回测报告 ×4 + 归因报告 |


## 三、各阶段明细


### S1 环境与数据可达性(10-05)

- 环境:MT5 build 6231 跑在 Wine 上,账户 Pepperstone-Demo(模拟账户),共 1,732 个品种。
- 网络受限,逐一实测数据源:SEC EDGAR 可用(UA 必须带邮箱)、stockanalysis.com 可用;Yahoo(直连 403 / 走代理 429)、Stooq(反爬)、东方财富(限流)不可用。
- 结论:主数据源定为 SEC XBRL,股息率与价格对照用 stockanalysis,交叉验证改用「SEC 内部双算法」替代。


### S2 标的池清洗(10-05)

- 输入:原脚本里的 100 个美股代码(带 .NYS / .NAS 等交易所后缀)。
- 动作:写 EnumUSStocks 脚本枚举券商端真实品种,逐个匹配。
- 结果:Pepperstone 不提供其中 19 个(HYG GLD VNQ BK VBK VGT ZTO YY BHP VALE BILI TCOM MOMO EDU PDD EA TWLO SQ DJT),最终池 = 81 个基础代码。
- 副产品发现:DJT 在券商描述里是「Dow Jones Transportation Average」(道指运输指数),与「特朗普媒体 DJT」撞名,已注释停用。
- 动作:新的合约解析规则——候选顺序 代码.US → 代码.US-24 → 纯代码,谁在回测区间内真有足够 K 线就用谁。


### S3 价格稳定性选股(10-05)

- 输入:81 只、M30、2025 全年数据。
- 动作:把原脚本移植为 ScreenUSStocks.mq5,只改工程适配(合约解析、基准自动识别、取不到区间数据时回退最近 N 根、逐只进度打印),指标体系与打分逻辑一行未改。
- 产出:reliability_ranking.csv / .xlsx +《美股价格稳定性排序》报告。
- 关键结论:一类 36 只、二类 45 只;评分与年化收益的相关系数 −0.31,与最大回撤 −0.89 —— 这套评分本质是「回撤规避分」,不是收益预测。
- 同时发现口径问题:原脚本按 24 小时折算年化(12,096 根),比美股实际的 3,276 根高 3.69 倍,已在新报告的收益列里修正。


### S4 基本面因子(10-08)

- 输入:SEC XBRL 三大报表 + stockanalysis 价格。
- 动作:写 fetch_fundamentals.py(支持 --asof 点时快照、--out-name、--selftest),实现 9 步预处理;核心 7 因子 + 扩展 5 因子。
- 产出:3 份快照(2024-12-31 用 2024Q3 财报、2026-06-30 用 2026Q1 财报、最新)+ 逐标的审计文件 + 因子设计文档。
- 过程中修掉 3 个取数 bug:YTD 累计值未还原成离散季度、陈旧标签(把 2014 年的营收当成当期)、负权益导致 ROE 失真(MCD 出现 −859%)。
- 过滤结果:81 只 → 有 CIK 78 只 → 覆盖 71 只 → 保留 56 只(最新快照)。


### S5 截面回测 EA(10-05 ~ 10-09)

- 输入:选股逻辑 + 因子表。
- 动作:写 CrossSectionalRankEA.mq5——每个调仓日只用「仅过去」的数据重算全池指标与分数,按稳定性评分或动量排序,取前 8 名等权持有 21 天;并加上基本面过滤、股票池从文件读取、股息内部记账、以及写诊断 CSV 的能力。
- 诊断手段:测试器不保存 EA 的 Print 输出,所以把每期每只标的的状态写进 Common/Files/cs_diag.csv,把运行摘要写进 cs_run_report.csv —— 这是后面能快速定位问题的关键。
- 产出:EA + 4 组参数集(2025 评分 / 2025 动量 / 2026H2 评分 / 2026H2 动量)。


### S6 回测与归因(10-09)

- 四组对照:2025 全年 ×(评分, 动量) + 2026.07–10 ×(评分, 动量),另外补两个「同池等权买入持有」基准。
- 结果:2025 动量 +19.21%、评分 +3.96% vs 基准 +24.30%;样本外 −1.14% / −2.99% vs 基准 +2.66%。
- 归因:无正超额;成本(隔夜利息年化 6%+)与评分维度是主要拖累;风控有效。
- 产出:4 份回测 xlsx + 3 份运行报告 + 归因报告 + 结果汇总表。

## 五、问题清单与解决过程

| # | 问题 | 表现 | 解决办法 |
|---|---|---|---|
| 1 | 代码带交易所后缀 | 原池写的是 HYG.NYS 这类,Pepperstone 端不存在该写法 | 改用基础代码 + 自动解析(.US → .US-24 → 纯代码) |
| 2 | 19 个代码无对应 | 券商端根本没有这些品种 | 剔除,池子定为 81 只 |
| 3 | 脚本拖上图后立刻 removed | 输入参数里的品种无法选择(基础代码) | 修正品种解析,不再因 SymbolSelect 失败而丢标的 |
| 4 | MT5 字符串参数有长度上限 | 81 个代码塞进 EA 输入会被截断,只剩一小半 | 股票池改为直接读基本面快照文件(InpPoolFromFile) |
| 5 | CSV 字段含逗号 | sector / entity 带逗号导致整行列错位 | 导出改 QUOTE_NONE,把逗号替换成分号 |
| 6 | YTD 累计披露 | 利息费用等因子覆盖率只有 54% | 按期间长度识别,用相邻两期相减还原离散季度 |
| 7 | 陈旧标签污染 | JPM 的 Revenues 取到了 2014 年的值 | 按报告日过滤 + basis_fy 标记年报兜底 |
| 8 | 负权益导致 ROE 失真 | MCD 算出 ROE = −859% | 负权益直接判该因子缺失 |
| 9 | Yahoo 不可用 | 直连 403、走代理 429 | 改用 SEC 内部双算法校验 + 值域检查 |
| 10 | 前视偏差 | 2026 年 1–6 月用了 2026-06-30 的快照 | 改为点时快照:只用回测起点之前已公布的财报 |
| 11 | CFD 是否含股息 | 回测净值可能系统性低估 | 独立写测试脚本对照:确认 CFD 报价 = 未复权股价,股息不在报价里;EA 内部单独记账 |
| 12 | 回测「只做两笔就爆仓」 | 柱数只有 232(正常 10,689),账户被打穿 | 定位为测试器勾选了「以点数计算的盈利」:每笔盈亏被放大 100 倍;改回「按资金」后恢复正常 |
| 13 | 单标的上限形同虚设 | 2025.04.17 出现 65 手 KO + 37.3 手 TJX,100% 押两只票 | 截顶后不再归一化回补,不足 N 只时留现金 |
| 14 | 编译警告 | OrderCalcMargin 未检查返回值 | 改为 if(!OrderCalcMargin(...)) 并写入诊断列 |
| 15 | 参数找不到、算不清 | InpFundFile 等参数不知道在哪里改 | 统一做 4 份 .set 参数集放到 MQL5\Profiles\Tester\,加载即可 |


## 六、复现手册(标准操作步骤)

1. 刷新基本面(每季度一次):运行 python3 scripts/us_stocks/fetch_fundamentals.py --asof YYYY-MM-DD,脚本会自动把快照复制到 MT5 的 Common\Files。
1. 把 mql5/Experts/US/CrossSectionalRankEA.mq5 复制到 MT5 的 MQL5\Experts\US\,在 MetaEditor 里按 F7 编译(应显示 0 errors, 0 warnings)。
1. 打开策略测试器:专家 = CrossSectionalRankEA,品种 = MCD.US-24,周期 = M30,模式 = 每笔订单基于真实点位,延迟 = 1 毫秒,入金 = 10000,杠杆 = 1:100。
1. 确认「以点数计算的盈利」这个勾选框是未勾选状态(勾了就一定会爆仓),日志里应出现 initial deposit 10000.00 USD。
1. 在「设置」里改回测区间(2025.01.01–2025.12.31 或 2026.07.01–2026.10.08),在「输入参数」右键 → 加载对应的 US_*.set。
1. 点开始。跑完取三样东西:测试器报告(xlsx 另存)、Common\Files\cs_diag.csv、Common\Files\cs_run_report.csv。
1. 每次新增文件都要明确「仓库路径 → MT5 目标路径」,报告按 01_选股 / 02_基本面因子 / 03_回测 / 04_工作报告 归类。

## 八、遗留问题与后续计划

1. 排序逻辑重做:稳定性评分维度在 2025 是负贡献,需要重构或删除;下一步做「动量 + 质量」混合排序对照。
1. 样本外样本太短:2026H2 只有 3 个月、5 次调仓,需要延长区间并做滚动窗口验证。
1. 成本优化:隔夜利息年化 6%+,应测试 42/63 天调仓周期。
1. 现金拖累:把「不足 N 只留现金」改成「按分数补齐 N 只」做一版对照。
1. 数据源补齐:跨厂商交叉验证(Yahoo 或付费 API)仍然缺失。
1. 实盘执行未验证:点差、滑点、盘前盘后流动性都会影响实际成交,回测未覆盖。
